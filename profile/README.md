<p>稳定性不是一句很稳就能说清的，它由线路冗余、地址历史、上游带宽和运维响应共同决定。本文先拆开稳定性的实际含义，再给三条可量化的观察指标，接着列出掉线的排查顺序，然后用一张参数核对表把询价项目固定下来，最后说明观察期怎么走。</p>
<h2>一、稳定指的是哪几件事</h2>
<p>双ISP的本意是一条线路接两家上游，主线路故障时自动切到备用。它能解决单点断网，解决不了地址被平台标记、或者上游超卖带宽。</p>
<p>所以问稳不稳，先分清担心的是物理断线还是地址被拒。前者看冗余与切换速度，后者看地址段的历史和登记信息，解法完全不同。</p>
<p>还有一层常被忽略，就是设备侧。路由器性能不足、NAT 表打满、散热不好，都会表现为时好时坏，这时候换供应商也修不好。</p>
<h2>二、三条能落到数字上的指标</h2>
<p>第一条是月度可用率。正规服务商能给出去年逐月的掉线记录，双上游做得好的在 99.5% 以上，单线往往在 99% 附近。</p>
<p>第二条是切换耗时。秒级切换对直播和通话几乎无感，分钟级切换对上传大文件的影响就很明显了。</p>
<p>第三条是高峰丢包。晚八点到十一点最挤，这个时段连 ping 一千个包，丢包压在 1% 以内算合格。</p>
<h3>为什么方差比平均值重要</h3>
<p>两台机器平均延迟一样，一台平稳，一台每小时抖一次，体感差很远。问指标时多要一个最大值，比只看平均值有用。</p>
<h2>三、掉线了按什么顺序查</h2>
<p>排查从外到内，先确认上游是不是全网故障，再看专线终端指示灯，然后看路由器 WAN 口状态，最后才怀疑地址本身。</p>
<p>ping 网关正常但出不去，多半是 DNS 或路由表的问题；连网关都丢包，问题在物理链路，找服务商报障才有意义。</p>
<p>把故障时间点和现象记下来，比一句又断了有用。连续三次同一时段出问题，通常指向上游拥塞而不是偶发事故。</p>

<h3>平台验证不等于线路故障</h3>
<p>打开网页要短信验证、登录要二次确认，是平台侧的风控动作，跟通断无关。两类问题混着报障，只会拖慢真正的处理。</p>

<h2>五、把价格算成三年总账</h2>
<p>只看月费容易吃亏。初装费、IP 加购费、超流量单价、换 IP 是否收费，这四项加起来能拉开三成以上的差距。</p>
<p>双 ISP 的价值在冗余。业务能容忍几小时中断，为冗余付的钱就不划算；靠这条线吃饭，省下的月费不够一次断线损失。</p>
<p>美国双 ISP 住宅服务器的月费大致在几百到一千多元，含多个静态地址的套餐更高，以当期报价为准，仅供参考。</p>
<h3>按月付还是按年付</h3>
<p>年付通常有折扣，也把风险锁死了一整年。先月付跑两个月，确认稳定再谈年付，是更稳妥的做法。</p>
<h2>六、观察期怎么过</h2>
<p>拿到机器先别上业务，头三天做连续探测，每小时记一次延迟、丢包和出口地址，确认地址不会自己变。</p>
<p>一周内把业务跑起来但保留回退方案，两周后再决定是否长期续费。这个节奏比任何口头承诺可靠。</p>
<p>响应速度也要试。提一个普通工单，看首次回复用了多久，这个数字比销售说的七乘二十四真实。</p>
<h2>常见问答</h2>
<h3>双 ISP 就一定比单线稳吗？</h3>
<p>答：物理链路上确实多一层冗余，但前提是两家上游走不同城域网。若两条线最终进同一台设备，冗余会打折。</p>
<h3>共享带宽的套餐能买吗？</h3>
<p>答：能买，但要清楚它的下限可能很低。问清保底带宽是多少，再按最坏情况估算业务受不受得了。</p>
<h3>静态 IP 用一段时间会变吗？</h3>
<p>答：正规静态套餐在合同期内不变。若出口地址变了，先查路由器是否重播号，再向服务商要变更记录。</p>
<h3>价格越低风险越大吗？</h3>
<p>答：不完全线性。明显低于同类的报价，通常在超卖带宽、复用地址或退款期上做了削减，逐项问清即可判断。</p>
